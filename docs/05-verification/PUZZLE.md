## 게임 설계 요약

- **규칙은 엔진(`engine.ts`, React 없음), 화면은 재생만.** `resolveMove()`가 연쇄 단계(`steps`)를 돌려주고 화면이 애니메이션으로 재생한다 → 규칙을 브라우저 없이 테스트(`pnpm test:puzzle`).
- 종류 6가지(비닐·플라스틱·캔·종이·유리·일반), 색 **과** 모양이 모두 달라 색만으로 구분하지 않는다.
- 특수 블록: 4개 → 줄 폭탄 · L/T자 → 구역 폭탄(5×5) · 5개 한 줄 → 분리수거 폭탄(같은 종류 전부).
- 점수: 칸당 10점 × 연쇄 배수(×1·×2·×3·×4, 최대 ×4) + 특수 블록 생성 50 + 3연쇄부터 보너스.
- 시간: 60초 시작, 최대 90초, 칸 수·연쇄에 따라 회복. **터지는 동안 시간 정지**(연쇄 애니메이션이 시간을 깎으면 불공평).
- **일시정지:** 버튼·`P`/`Esc`·탭 숨김 시 자동. 타이머와 입력을 멈추고, 판은 불투명 오버레이로 가려 멈춘 채 수를 보는 것을 막는다(터지는 애니메이션 중에 눌러도 시간은 이미 정지 상태라 불이익 없음).
- 점수·시간 수치는 **게임 밸런스 초기값**이다(환경 수치 아님 → "수치를 만들지 않는다" 규칙과 무관). 판 아래에 "실제 분리배출은 지역마다 다르니 클라우드 랩에서 확인" 안내를 붙인다.

## P1. 게임 오버 화면의 "다시 하기" 버튼이 눌리지 않는다

**문제 발견**
- Playwright로 가만히 두어 시간 종료까지 간 뒤 "다시 하기"를 누르려 하자 30초 동안 클릭이 실패했다.
- 로그: `<button data-cell="4-4" ...> intercepts pointer events` — 버튼이 보이는데 클릭이 **타일 버튼**으로 갔다.

**원인**
- 타일에는 `z-index`(선택 5 · 특수 2 · 일반 1)를 줬는데 종료·시작 오버레이에는 `z-index`가 없었다. 쌓임 순서에서 타일이 오버레이 위에 그려졌다.
- 시작 전에는 타일이 없어서(`ready`) 드러나지 않았고, **타일이 남아 있는 종료 화면에서만** 문제였다.

**해결 과정**
- 층을 정리했다: 타일 1~5 < 콤보 배너·알림 10 < 시작/종료 오버레이 20.

**근거**
- 오버레이는 "그 아래 모든 입력을 막는 것"이 목적이라 타일보다 항상 위여야 한다. 타일의 z-index를 낮추는 방식은 선택·특수 블록 강조(위로 올라옴)를 깨므로 쓰지 않았다.

**결과**
- 시간 종료 → "다시 하기" → 새 판 시작(진행 막대 59) 통과, 콘솔 오류 0건. 규칙은 `frontend/AGENTS.md` §3-2에 기록.

## P2. 상태 업데이트 함수 안에서 교환을 실행하면 개발 모드에서 두 번 실행될 수 있다

**문제 발견 (코드 검토 중 발견, 재현 전에 예방)**
- 첫 구현의 `tap()`이 `setSelected((cur) => { ... swap(cur, ...) ... })`처럼 상태 업데이트 함수 안에서 `swap`(부수 효과)을 호출했다.

**원인**
- React 개발 모드(StrictMode)는 업데이트 함수를 **두 번** 호출해 순수성을 점검한다. 부수 효과가 들어 있으면 같은 교환이 두 번 시도된다(현재는 `busy` 가드가 막아 줄 뿐, 우연에 기댄 구조).

**해결 과정**
- 현재 선택 값을 클로저에서 직접 읽고, 분기마다 `setSelected`와 `swap`을 **따로** 호출하도록 바꿨다. 포인터 핸들러는 렌더마다 최신 `tap`을 가리키도록 ref로 갱신한다.

**근거**
- 상태 업데이트 함수는 순수해야 한다는 React 규칙. 가드에 기대는 것보다 구조로 해결하는 편이 안전하다.

**결과**
- 클릭 교환·밀기 교환·안 터지는 교환(제자리 복귀)·자동 40수 플레이 모두 통과, 중복 교환 없음.

## P3. 규칙 테스트 스크립트를 `pnpm lint`가 막는다 → 셸 무관하게 실행

**문제 발견**
- 규칙 테스트를 `scripts/test-trash-match.cjs`(CommonJS)로 추가하자 `pnpm lint`가 `no-require-imports` 오류 2건을 냈다.
- ESM으로 바꾸고 `package.json`에 `tsc … && node -e "…"` 한 줄 명령을 넣었더니, 따옴표 이스케이프가 Windows 셸(cmd/Git Bash)마다 달라 깨질 수 있었다.

**원인**
- 린트 규칙이 `.cjs`의 `require`를 금지했고, `package.json`의 긴 한 줄 명령은 셸 의존적이다.

**해결 과정**
- 테스트 파일을 `.mjs`(ES 모듈)로 바꾸고, **컴파일(TypeScript API 경로 해석) → `.tmp-puzzle/package.json`(type: module) 작성 → 동적 import**를 테스트 파일이 직접 수행하게 했다. `package.json`에는 `"test:puzzle": "node scripts/test-trash-match.mjs"`만 둔다.

**근거**
- 셸 문법에 의존하지 않는 Node 스크립트가 Windows·macOS·CI에서 같게 돈다. 프로젝트의 린트 규칙도 그대로 지킨다(규칙을 끄지 않음).

**결과**
- `pnpm test:puzzle` 통과(초기 보드 200개 · 특수 블록 생성/발동 · 잘못된 교환 · 콤보 배수 · **4,345회 이동 시뮬레이션** — 끝난 보드에 터질 곳 없음 / 움직일 곳 있음 / 빈칸 없음, 최대 연쇄 10), `pnpm lint` 통과.

## P4. 요청 의도 오해 — "탭으로 추가"가 아니라 "교체"

**문제 발견**
- "국가 비교 기능 부분에 게임을 넣어줘"를 처음에는 **기존 비교는 두고 탭을 추가**하는 것으로 구현·머지(PR 4개)했다. 이후 사용자가 "국가 비교는 빼고 게임으로, 비교 기능은 지워라"라고 정정했다.

**원인**
- "넣어줘"를 추가로 해석했고, 기존 기능을 유지할지 확인하지 않았다.

**해결 과정**
- 이미 머지된 탭 구조(PR 1~3)를 되돌리지 않고, **그 위에 단계별로** 교체했다: ① `/game` 전용 화면과 메뉴 교체 → ② 국가 비교 코드·문구·API 클라이언트 삭제와 `/vs` 리다이렉트 → ③ 쓸모없어진 게이트웨이 엔드포인트 삭제 → ④ 문서. 각 단계가 독립적으로 빌드·테스트를 통과한다(화면이 깨지는 시점 없음).
- 같은 시점에 열려 있던 문서 MR(`phase-8/docs-puzzle`)은 낡은 내용("탭")을 담고 있어서, 그 브랜치 위에 최신 내용을 덮어써 한 번에 정리했다.

**근거**
- 이력(PR 번호)을 지우거나 force-push하지 않고, 되돌림 대신 **앞으로 가는 변경**으로 바로잡는 편이 추적 가능하고 안전하다.
- 삭제 범위는 "호출하는 곳이 없어진 것"으로 한정했다: 프론트 화면·클라이언트 함수·전용 문구·게이트웨이 `/series`. rag-service `wb_series`와 발견 노트의 예전 `compare` 기록은 **쓰는 곳이 남아 있어** 유지했다.

**결과**
- `/vs` → 308 → `/game`, 메뉴 "분리수거 게임", 게임 시작 시 타일 64개, 콘솔 오류 0건. 게이트웨이 테스트 13/13.

## P5. 줄·구역 폭탄이 "옮기기만 해도" 터진다 (요청 정정)

**문제 발견**
- 사용자 피드백: "줄 폭탄은 해당 색과 같이 지워졌을 때 작동해야 한다. 폭탄을 눌러 옆으로 이동시키면 무조건 작동하는 건 아니다."
- 첫 구현은 특수 블록을 교환하는 순간 종류와 상관없이 발동(`forced`)시켰다.

**원인**
- 분리수거 폭탄(색이 없어 맞출 수 없는 블록)의 "바꾸면 발동" 규칙을 줄·구역 폭탄에도 같이 적용했다. 줄·구역 폭탄은 **색이 있어서 매치에 참여할 수 있으므로** 매치로 터뜨리는 것이 맞는 설계였다.
- 움직일 곳 판정(`hasMove`)도 "특수 블록이 있으면 움직일 수 있음"으로 같은 가정을 해서, 폭탄만 남은 막힌 판을 막히지 않은 판으로 오판할 수 있었다.

**해결 과정**
- `resolveMove`: 교환 시 **분리수거 폭탄(`color`)만** 발동(`forced`). 줄·구역 폭탄은 같은 종류 3개 이상 매치에 포함되어 터질 때만 발동하고, 매치가 없으면 교환을 되돌린다(`null`).
- `hasMove`: 분리수거 폭탄이 있을 때만 "움직일 수 있음"으로 인정.
- 게임 안 설명 문구(4개 언어)와 `frontend/AGENTS.md`를 새 규칙으로 갱신.

**근거**
- 캔디 크러시류 3-매치의 일반 규칙과 같고, 사용자가 요구한 동작이다. 색이 없어 맞출 방법이 없는 블록만 바꾸기로 발동해야 "쓸 수 없는 블록"이 생기지 않는다.
- 줄 폭탄이 터질 때 그 줄 안의 다른 특수 블록은 연쇄로 함께 터지는 기존 동작은 유지했다.

**결과**
- 규칙 테스트에 시나리오 추가 후 통과: 줄·구역 폭탄을 매치 없이 옮기면 `null`(제자리) / 같은 종류와 함께 맞추면 줄 전체·5×5 발동 / 분리수거 폭탄은 바꾸기만 해도 발동 / 폭탄만 있는 막힌 판은 "움직일 곳 없음". 4,345회 이동 시뮬레이션 그대로 통과.
