## T1. 입장/퇴장 알림이 너무 자주 뜬다

**문제 발견**
- 두 브라우저로 테스트하는 동안 대화 사이에 "지구미님이 나갔습니다 / 들어왔습니다"가 계속 끼어들었다. 3회 테스트한 방의 시스템 알림이 메시지보다 많아졌다.
- 다른 메뉴(발견 노트)로 갔다 돌아오기만 해도 퇴장·입장 알림이 한 쌍씩 쌓였다.
- 목록에서 방 카드를 스치듯 눌러도 바로 입장 처리되어 "들어왔습니다"가 남았다.

**원인**
- 1차 구현은 **"소켓이 방 채널에 붙어 있다 = 방에 있다"** 로 정의했다(`Presence.enter/exit`).
  화면 이동·새로고침·네트워크 끊김이 모두 "방을 나감"으로 해석됐다.
- 새로고침 대비로 4초 유예(`LEAVE_GRACE_MS`)를 두었지만 증상만 줄였을 뿐, **"보고 있음"과 "참여함"이 한 상태에 섞여 있다**는 근본 원인은 그대로였다.

**해결 과정**
1. 상태를 둘로 나눴다 — `domain/presence.ts`의 `Roster`
   - **참여(membership)**: `join`(확인) 때 생기고 `remove`(나가기) 때만 사라진다.
   - **접속(connection)**: 방 화면을 연 소켓 수. 접속자 표시(초록 점, "N명 보는 중")에만 쓴다.
2. 유스케이스를 4개 동작으로 분리 — `community.service.ts`

   | 소켓 이벤트 | 유스케이스 | 알림 |
   |---|---|---|
   | `room:join` | 참여 확인 → 명단 추가 + 열기 | 처음 참여할 때만 "들어왔습니다" |
   | `room:open` | 참여한 방 다시 열기 (미참여면 `not_member`) | 없음 |
   | `room:close` / 연결 끊김 | 화면에서 나옴, 참여 유지 | 없음 |
   | `room:exit` | "나가기" → 명단에서 제거 | "나갔습니다" |
3. 메시지·첨부·리액션·메모 권한도 "접속"이 아니라 **"참여"** 로 검사한다(`mustBeIn` → `isMember`).
4. 프론트: 방 목록 API가 `joined`를 돌려주고, 미참여 방은 **"○○에 참여하시겠습니까?"** 확인 창을 거친다. 방 헤더에 **나가기**(확인 한 번 더) 버튼을 두었다.
5. 4초 유예 타이머·`OnModuleDestroy`·`pendingLeaves` 맵을 삭제했다.

**근거**
- 사용자가 요구한 동작이 카카오톡 모델("이미 들어와 있으면 안 뜨고, 나가기·퇴출 때만 뜬다")이다.
- 알림은 **사람의 의사 표시**(참여/나가기)에만 붙어야 한다. 네트워크 상태는 사람의 의사가 아니다.
- 상태를 나누면 유예 타이머 같은 우회책이 필요 없다. 타이머가 없으니 정리할 자원도 경쟁 조건도 없다.

**결과**
- 게이트웨이 테스트 `카카오톡식 참여` 시나리오: 참여 전 `room:open` 거절 → 참여 1회 알림 → 다른 탭 열기·재참여·탭 닫기·메뉴 이동 **알림 0건** → 나가기 1회 알림 → 나간 뒤 메시지 거절. **통과.**
- 브라우저(Playwright, 3000/3001): 취소하면 입장 안 됨, 발견 노트에 갔다 돌아와도 알림 수 변화 없음, 재입장 시 확인 창 없이 바로 열림, 나가기 → 상대 화면에 "지구미님이 나갔습니다." **통과, 콘솔 오류 0건.**
- 퇴출(kick)은 `Roster.remove()` + 퇴장 알림을 그대로 재사용하면 된다(방장 권한이 생기면 이벤트 하나만 추가).

## T2. 홈 지구본 위에 지구 친구가 엉뚱한 곳에 뜬다

**문제 발견**
- 홈 지구본 영역 왼쪽 아래(지구본·범례 위)에 지구 캐릭터가 겹쳐 보였다(사용자 스크린샷).
- DOM을 재 보니 `EarthBuddy`의 위치가 `x = -70px`, `position: relative` — 지정한 `absolute right-2 bottom-2`가 적용되지 않았다.

**원인**
- `EarthBuddy` 컴포넌트가 루트에 항상 `relative`를 붙이고 바깥 `className`을 뒤에 합쳤다.
  Tailwind는 클래스 **적는 순서가 아니라 생성된 CSS 순서**로 이기므로, `relative`가 `absolute`를 덮어 일반 흐름에 배치됐다.
- 같은 버그가 `/about`의 `EarthBuddy className="absolute ..."`에도 숨어 있었다.

**해결 과정**
- `entities/mascot/characters.tsx`: 바깥에서 `absolute`/`fixed`를 주면 `relative`를 붙이지 않도록 수정(근본 수정, `/about`도 함께 해결).
- 홈(`app/page.tsx`)은 위치를 바깥 래퍼가 잡게 하고, **구름(오른쪽 위) 바로 왼쪽**으로 옮겼다(64px).

**근거**
- 실제 렌더 결과(`getBoundingClientRect`, `getComputedStyle`)로 원인을 확인했다. 추측으로 위치 값만 바꾸면 다른 화면에서 재발한다.

**결과**
- 수정 후 `x = 558, y = 445, 64×64` — 구름 왼쪽에 나란히, 지구본·범례와 겹치지 않음(스크린샷 확인).

## T3. 라이트 모드에서 상대 말풍선이 배경과 구분되지 않는다

**문제 발견**
- 흰 카드 위에 상대 말풍선(`bg-surface-2` = `#f2f6fa`)이 거의 보이지 않았다.

**원인**
- 말풍선이 "일반 표면" 토큰을 빌려 썼다. 배경도 흰색 계열이라 대비가 부족했다.

**해결 과정**
- 채팅 전용 토큰을 만들었다 (`globals.css`, 라이트/다크 각각):
  `--chat-bg` · `--bubble-mine`(=accent) · `--bubble-other` · `--bubble-*-ink`.
- 상대 말풍선은 **내 말풍선색(남색 `#25354d`)을 연하게 한 불투명 색** `#dde5f0`, 다크는 `#2e3d56`.
- 대화 영역 배경을 `--chat-bg`(`#f4f7fb` / `#172131`)로 카드와 분리했다.

**근거**
- `bg-accent/20` 같은 **투명도 방식은 쓰지 않았다**: 뒤에 깔린 색(대화 배경·카드·그라데이션)에 따라 색이 달라져 곳곳에서 비쳐 보인다(사용자 지적). 불투명 색을 직접 골라야 모든 위치에서 같은 색이 나온다.
- 다크 모드는 내 말풍선이 밝은 색(`#e4ecf6`)이라, 상대 말풍선은 배경보다 한 단계 밝은 남색으로 잡아 세 색이 모두 구분되게 했다.

**결과**
- 라이트/다크 스크린샷에서 내 말풍선·상대 말풍선·배경 세 색이 분명히 구분됨.

## T4. 코드는 맞는데 말풍선 색이 안 나온다 (개발 서버 CSS 캐시)

**문제 발견**
- T3 적용 후 사용자 개발 서버 화면에서 말풍선 배경이 아예 없었다.

**원인 추적**
1. 소스 확인: `globals.css`의 `:root`·`@theme`에 토큰 존재 ✔
2. 실행 중인 페이지의 **CSS 규칙 전체에서 "bubble" 검색 → 0건**(`:root` 변수조차 없음) → 소스가 아니라 **실행 중인 dev 서버가 이전 CSS를 들고 있음**
3. `pnpm build` 결과물에는 `.bg-bubble-mine{background-color:var(--bubble-mine)}` 존재 ✔

**해결**
- 코드 수정 없음. 프로덕션 빌드를 별도 포트(3005)로 띄워 정상 표시를 확인했다.
- 사용자 개발 서버는 **재시작**하면 반영된다.

**근거·교훈**
- "화면이 이상하다 → 코드부터 고친다" 대신 **소스 → 실행 중인 CSS → 빌드 결과물** 순서로 어느 층에서 끊겼는지 먼저 확인했다.

## T5. 캐릭터 이미지가 깨져 보인다

**문제 발견**
- 구름·지구 캐릭터 가장자리가 뭉개지고 흐렸다.

**원인**
- 원본 PNG가 약 140~270px인데 112px로 표시 → 2배 화면(레티나·대부분의 휴대폰)에서는 **224px가 필요**해 브라우저가 늘려서 그렸다. 애니메이션(`transform: scale`) 중에는 더 흐려진다.

**해결 과정**
- `frontend/scripts/upscale-characters.py`: 원본은 그대로 두고 `@2x`·`@3x` 생성
  - **premultiplied alpha(RGBa)** 로 리사이즈 → 투명 가장자리가 검게 번지지 않음
  - Lanczos 확대 + 약한 언샤프 마스크
- `charImg(name)` → `src` + `srcSet(1x/2x/3x)`, 모든 캐릭터 `<img>`에 적용(헤더·홈·Cloud Lab·마스코트).
- 홈 지구 친구 표시 크기를 112px → 64px로 줄였다(원본 1배 안팎).

**근거**
- 브라우저의 실시간 확대(쌍선형)보다 미리 고품질 필터로 만든 이미지가 윤곽이 깔끔하다.
- 원본보다 **디테일이 생기지는 않는다**. 완전히 선명하게 하려면 더 큰 원본으로 교체해야 한다(문서에 명시).

**결과**
- `@2x` 확인 결과 가장자리 계단·검은 테두리 없음. 2배 화면에서 맞는 해상도를 받아 흐림이 줄었다.

## T6. `EADDRINUSE` — 포트가 이미 사용 중

**문제 발견**
- 사용자가 `pnpm dev:both` / `pnpm dev` 실행 시 3000·3001·4000 포트 점유 오류.

**원인**
- 검증용으로 띄운 서버를 종료할 때 **래퍼 프로세스(pnpm/셸)만 멈추고** 실제 node·python 프로세스가 남았다(Windows는 자식 프로세스가 함께 종료되지 않는 경우가 있다).

**해결**
- 포트별 소유 프로세스를 `Get-NetTCPConnection`으로 찾아 **명령줄을 확인**한 뒤(검증용으로 띄운 것만) 종료.
- 하네스(`AGENTS.md` §4)에 "서버를 끝낼 때 포트로 실제 프로세스까지 종료됐는지 확인" 규칙 추가.
- 이후 검증은 사용자 서버가 떠 있으면 **건드리지 않고** 그 위에서 하거나 별도 포트(3005)를 썼다.
